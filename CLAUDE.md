# Notes for Claude

## The command line has steghide's syntax

ScatterSteg competes with steghide, so its command line uses steghide's commands and option names for every feature ScatterSteg has: a steghide user should only have to type `scattersteg` instead of `steghide`. The commands are `embed`, `extract`, `info`, `encinfo`, `version`, `license` and `help` (each also as `--embed` and so on); the options are `-ef`, `-cf`, `-sf`, `-xf`, `-z`, `-Z`, `-N`, `-f`, `-q`, `-v`, with steghide's long forms (`--embedfile`, ...).

- **Syntax only, never steghide's text.** Messages, prompts and help text are ScatterSteg's own wording. Don't copy or paraphrase steghide's.
- **New features:** if steghide has an option or command for the same thing, use its name and meaning. If not, pick a name that doesn't clash with one of steghide's. ScatterSteg's own extras so far: the `passphrase` command, `info`'s capacity and suggested-payload lines, and `embed`'s warning when a message is over the suggestion.
- **Deliberate differences, not bugs** (the README's "Coming from steghide" lists them for users):
  - `-p <passphrase>` is refused, with an explanation: the passphrase is always typed at the prompt, never on the command line where `ps` and shell history would show it. The owner decided this; don't add `-p`.
  - `-e` and `-K` are refused: the encryption is fixed (XSalsa20-Poly1305) and every message is authenticated.
  - `-cf -` and `-sf -` (cover from stdin, output to stdout) aren't supported.
  - An existing output file is refused unless `-f`; there is no yes/no prompt.
  - `info <image>` reports whether the image can be a cover, its capacity, and a suggested most to store (a byte per 160 pixels or non-zero AC coefficients, from the benchmarks' lightest payload). It doesn't look for a message: nothing can, without the passphrase.
  - Messages are always byte-exact (no newline added or removed).
- **Both front ends:** `main.c` (C) and `rust/src/main.rs` (Rust) must behave identically, wording included. `tests/test_cli.py` runs against each (`SCATTERSTEG=<binary>`).

## Detectability plan (2026-10-31)

The file format isn't frozen: nobody uses ScatterSteg yet, so a format change needs no compatibility path. Each step is measured before it's kept; every change lands in C and Rust together, with `FORMAT.md` and the tests. The README's "Status and plans" is the public version of this list.

0. **Done, merged:** `main` refuses JPEG covers carrying a content credential (C2PA), which the changes would visibly break. From the 2026-10-31 threat-model review, which also added pooled evidence, how files travel, unseen copies of the cover and device seizure (A7) to `THREAT_MODEL.md`.

1. **JPEG: embed in every AC coefficient** (zeros and ±1 included, UERD or J-UNIWARD costs, ±1 either way) instead of only |value| ≥ 2. UED, UERD and J-UNIWARD all do; nsF5-style skipping crowds the changes. Prototype in C on branch `jpeg-all-coefs` (`b702512`; 8 test checks still expect the old rule). **DCTR result (2026-10-31, `~/bench/run-distortion/results-allcoef.txt`):** P_E old → all-coefficients, UERD 0.485/0.464/0.397/0.261 → 0.473/0.456/0.418/0.356 at 0.05/0.1/0.2/0.3; J-UNIWARD 0.496/0.468/0.382/0.232 → 0.470/0.462/0.425/0.360. A clear gain from 0.2 up, slightly worse at 0.05 (1–2 sd; maybe tune a small extra cost on zeros, as `JPEG_TWO_COST` was tuned). Histogram shifts (`hist_jpg.py`, on `jpeg-all-coefs`) all ≤ 0.1 cover sds, against up to 1.6 (UERD) and 3.2 (J-UNIWARD) for the old rule at 0.3; every cover now fits 0.3. **Waiting on SRNet:** `uerdall_0.2` (stego from `~/bench/dl/embed_uerdall.sh`, build `b702512`) trains right after `hill_0.2`, initialised from `uerd_0.2`'s detector. That head start favours the detector, so a lower detection rate for `uerdall_0.2` is trustworthy; a higher one would need a from-scratch run (40 epochs, as `uerd_0.2` had) before concluding. Compare its P_E with `uerd_0.2`'s 0.073, **on the same test images**: `uerd_0.2` left out 45 of the 2,000 (smooth ones the old rule couldn't fit), `uerdall_0.2` should keep all. Each run's `runs/<set>/test_scores.npz` holds cover and stego scores in `split.txt`'s test order, skipping images with no file in `stego/<set>/`; drop those 45 from `uerdall_0.2`'s scores and recompute P_E with `metrics()` from `benchmark/dl/train.py`. Report both: the matched P_E (the comparison) and the full one. If SRNet agrees: update the tests, port to Rust, lift the carrier cap (`JPEG_MAX_CARRIERS` would refuse JPEGs above ~30 MP; store an index, not a pointer, per carrier), drop `JPEG_TWO_COST`, then an SRNet run in `~/bench/dl`.
2. **Write files the way the cover was written** (audit finding 7): the output's structure identifies ScatterSteg, and the C and Rust builds, without any steganalysis. **PNG done** (branch `cover-structure`, 2026-10-31): the cover's row filters, IDAT size and the zlib settings that reproduce its data (tried in a fixed order, same in C and Rust); C writes the file itself, Rust uses the system zlib, and `diff_png` checks the bytes match. 55 covers (Pillow, ImageMagick, zlib incl. Z_RLE) resave byte-identical; level-0 stored blocks can't always be matched. JPEG, next: keep the cover's scan script and Huffman tables where they still fit (step 1 can create values a camera's optimized tables lack). Ahead of the rest because it gives the file away whatever the pixels say.
3. **Ternary embedding** (multi-layer STC; the message picks +1 or −1): fewer changes per bit, as the published HILL/UERD/J-UNIWARD results assume. It removes most of the exchange embedding's swaps, so measure it against the current binary + exchange, don't assume.
4. **Payload suggestion by the square root law:** `info`'s suggested most should grow with √(pixels or non-zero ACs), not linearly.
5. **Know where we stand:** add HStego (J-UNIWARD/HILL with STC, the closest rival) and phasm-core (Rust, J-UNIWARD + STC), if it has a usable CLI, to the benchmark, and run Aletheia's detectors on ScatterSteg's output.
6. **Then stop chasing P_E:** user guidance in help and README (never a cover whose original exists anywhere else, fresh camera photos, small messages), a frozen format, a first release, an independent review. Later, maybe: synchronized changes (CMD/Synch). Not planned: a taller STC, adversarial embedding, side-informed JPEG.
